## Root cause

`scripts/check-restricted-content.sh` applied externally supplied text regular
expressions directly to compressed installer bytes through `rg --text`.
Release binaries are not reproducible byte streams: the exact same source and
toolchain passed run 30715950452, while the publication build's compressed
bytes happened to satisfy a policy regex. This is a binary representation
false positive, not evidence that the restricted text was embedded.

## Corrective boundary

The scanner now applies policy to printable ASCII strings universally and
UTF-16LE strings only for PE files, continues to fail on actual printable
restricted content, rejects extraction or scan errors, and scans explicitly
supplied bundle directories beneath `target`. Regression tests cover the
false-positive shape, non-PE binary handling, and both real Windows string
encodings. The pushed signed v0.98.12 tag is preserved; v0.98.13 is the next
candidate for rehearsal and publication.
