<objective>
Add seamless Mac→remote image paste via a daemon-brokered clipboard agent. Four atomic commits land:

1. **Broker route** on the server: WS for connected agents + POST request endpoint for TUIs, with X-Clipboard-Request-Id correlation through the existing uploads route.
2. **`agentum clip-agent` CLI** for macOS and Linux: long-polls every profile's daemon, reads the local clipboard via `arboard` on demand, uploads PNG via existing uploads route, with launchd/systemd unit install/uninstall/status/logs flags.
3. **TUI Ctrl-V flow**: broker-first, with the existing direct-arboard read remaining as the fallback when no agent is connected (so single-host users keep working).
4. **Install autostart**: `scripts/install.sh` calls `agentum clip-agent --install` for both fresh installs and updates; `agentum update --skip-clip-agent` propagates an opt-out env var to the spawned installer.

Purpose: Today, pasting an image from a Mac into a TUI running on a VPS requires SSH X-forwarding or a manual scp. After this work, the user copies an image on their Mac and hits Ctrl-V in the TUI — the daemon brokers the round-trip and the image lands as a normal session upload.

Output: One new server route module, two new CLI files, one new core function, three modified TUI/CLI files, one modified install script, one modified update command. Single-binary distribution preserved (clip-agent is an `agentum` subcommand, not a second executable).
</objective>
