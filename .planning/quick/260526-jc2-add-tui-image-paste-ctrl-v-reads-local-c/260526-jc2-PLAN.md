<objective>
Add `Ctrl-V` to the agentum TUI so the user can paste an image from their local OS clipboard directly into an agent's chat pane. The TUI reads the clipboard via the cross-platform `arboard` crate, PNG-encodes the RGBA pixels, and POSTs the bytes to a new daemon route `POST /api/sessions/{id}/uploads`. The daemon writes the file to `<session.workdir>/.agentum-uploads/<ts>-<rand>.png` and `tmux send-keys`s the relative path into the pane so the agent (Claude Code, Codex, Cursor, etc.) picks it up as an attachment the same way a file-path paste already does today.

Purpose: today's `Ctrl-K I` chord shells out to `wl-paste`/`pbpaste`/`xclip` *on whatever host the TUI runs on*. Over SSH or a remote `--profile` that means the wrong machine's clipboard. The arboard path reads the actual local clipboard the user sees on their screen, and the daemon-side write means the file lands next to the agent's working tree even when the daemon is running on a remote box (CLAUDE.md "WireGuard topology" and the named-profiles feature both depend on this asymmetry being addressable).

Output:
- One new daemon route module `routes/uploads.rs`, registered in `routes/mod.rs` and merged into `lib.rs::router()` inside the auth middleware layer.
- One new TUI HTTP client method `Client::upload_image`.
- One new Ctrl-V key handler in `app.rs::handle_key` that runs the clipboard read + PNG encode in `spawn_blocking`, then fires the upload off the main task.
- Two new TUI deps in `crates/agentum/Cargo.toml`: `arboard` (with `image-data` feature for `Clipboard::get_image()`) and `image` (with `png` feature, default-features off — we only encode, we don't decode arbitrary formats).
</objective>

    /// the bytes under <session.workdir>/.agentum-uploads/ and types the
    /// relative path into the tmux pane. Returns the relative path so the
    /// TUI can echo it in a toast.
    pub async fn upload_image(
        &self,
        id: Uuid,
        bytes: Vec&lt;u8&gt;,
        mime: &str,
    ) -&gt; Result&lt;UploadResponse&gt; {
        let url = self.base.join(&format!("/api/sessions/{id}/uploads"))?;
        let resp = self
            .http
            .post(url)
            .bearer_auth(&self.token)
            .header(reqwest::header::CONTENT_TYPE, mime)
            .body(bytes)
            .send()
            .await
            .context("upload_image request failed")?;

        }
        Ok(resp.json::<UploadResponse>().await?)
    }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TUI client → daemon HTTPS | Bearer-token-authenticated HTTPS body upload; daemon must validate session ownership before writing. |
| Daemon → filesystem | Daemon writes attacker-controlled bytes (image body) to a path under `<session.workdir>/.agentum-uploads/`. Filename is daemon-generated (timestamp + random hex + sanitized extension), NOT user-controlled. |
| Daemon → tmux pane | Daemon types the relative path into the pane via `send-keys`; the agent reads it as a file reference. The path is daemon-controlled (no Content-Type-derived directory components allowed). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-up-01 | Tampering | Filename construction in `uploads.rs` | mitigate | `sanitize_ext()` clamps extension to a known set ∪ `"bin"`; reject any `..` / `/` in mime-derived ext. Filename body is timestamp + 5-byte hex from a fresh UUID — never derived from headers or the body. |
| T-up-02 | Denial of Service | Upload body size | mitigate | 25 MiB inline cap + `axum::extract::DefaultBodyLimit::max(25 * 1024 * 1024)` applied to the route. Reject empty bodies (`body.is_empty()` → 400). |
| T-up-03 | Information Disclosure | Path traversal via session.workdir | mitigate | Reuse `super::util::expand_workdir` (already handles `~` safely and returns a `PathBuf`); join via `workdir.join(".agentum-uploads")` so `..` segments in workdir would have been rejected at session-create time. No user-supplied path component is ever joined. |
| T-up-04 | Spoofing | Unauthenticated upload | mitigate | Route is merged BEFORE `auth::require_token` is layered, inheriting bearer-token enforcement. Auth allow-list is NOT modified. Manual verify in done-criteria: `curl` without `Authorization` returns 401. |
| T-up-05 | Elevation of Privilege | send-keys injection via filename | mitigate | The relative path written to the pane has the shape `.agentum-uploads/YYYYMMDD-HHMMSS-XXXX.ext` — no spaces, no shell metacharacters, no Enter. `send_keys(target, &format!("{} ", path), false)` sends the literal string with `false` for append_enter. tmux's `send-keys` treats the body as literal text. |
| T-up-06 | Tampering | TUI clipboard handler reading host clipboard | accept | arboard reads the LOCAL OS clipboard; a malicious app on the same host could plant bogus image bytes, but this threat exists for any clipboard-aware app and is not in-scope for an AI agent control plane running on the user's own machine. |
| T-up-SC | Tampering | npm/pip/cargo installs (arboard, image) | accept | Both crates are widely used and present in major Rust app ecosystems (arboard: 1Password, Zellij, many TUIs; image: de-facto standard). No `[ASSUMED]`/`[SUS]` flag from RESEARCH.md is in play because this is a quick plan without research; the dep versions are pinned to the major series the dashboard already trusts (image 0.25 is what arboard 3 wants internally). |
