# Phase 1 — UI Design Contract

> Visual and interaction contract for the **dashboard `GoalComposer.svelte`**, the **TUI `Overlay::Goal`**, the **parent-cue chip** on child cards, and the **goal lbl** treatment. Generated by gsd-ui-researcher.

This phase introduces three visible surfaces:

1. **`GoalComposer.svelte`** — persistent input bar above the kanban board (dashboard).
2. **`Overlay::Goal`** — modal overlay reachable from the Board view (TUI).
3. **Parent-cue chip + `lbl="goal"` styling** — on every child card and on the goal card itself.

All three reuse the existing token system. **No new design tokens are introduced.** Phase 1's design contract is "specialise existing primitives" — composer is a `.toolbar`-style strip, parent-cue is a `.ticket .tk-foot .lbl` variant, and the goal lbl is a new `.lbl.goal` color slot.

## Interaction Contract

### `GoalComposer.svelte` (dashboard)

- **Placement:** between `.toolbar` and `.board` on the `/board` route. Reuses `.toolbar`-style padding (10px/16px) and chrome bg. **Full-width.** Does not collapse on mobile — on viewports ≤720px the layout becomes: textarea stacked above button (flex-direction: column; gap: 8px).
- **Default height (desktop):** 56px (compact). Textarea is **single-line by default**, expands to up to 4 visible rows as the user types (auto-grow via `rows={1}` + `style.height = scrollHeight`).
- **Max height:** 160px. Beyond that the textarea scrolls internally.
- **Focus behavior:** `:focus-visible` outline = 2px solid `var(--link)`, offset 2px (global rule in `app.css`). Border becomes `var(--link)` on focus.
- **Submit triggers:** (a) clicking "Plan it"; (b) `Cmd/Ctrl + Enter` while focused; (c) `Enter` **only when single-line and no shift** (multiline goals require explicit button or Cmd-Enter). Plain `Enter` inserts a newline once the textarea has wrapped beyond one line.
- **Disabled-state:** button is disabled when textarea is empty (length < 1 trimmed) OR `submitting === true`. Disabled opacity 0.45 (existing `.btn:disabled` rule).
- **After submit success:** textarea clears, focus stays on the textarea, button label resets to `Plan it`. Toast: NOT shown — the new goal card arriving on the board IS the feedback.
- **After submit failure:** error message renders **below the composer** (between composer and board, full-width, 4px `--crash` left border, `--fg-2` text on `--bg-2` bg, 8px vertical padding, 12px horizontal padding). Dismissable via a `×` button on the right. Auto-clears on next successful submit.
- **Keyboard accessibility:** textarea has `aria-label="Goal description"`. Button has implicit accessible name "Plan it". Error block has `role="alert"` and `aria-live="polite"`. Tab order: textarea → button → (any subsequent toolbar/board controls). After submit success, focus restoration: textarea.
- **Empty board state:** when **the board has zero `lbl=goal` cards AND zero children** (`board.column_order.length === 0` or all columns empty), the composer expands to an empty-state mode that shows the eyebrow (`GOAL`), the empty-state heading (`Drop a goal in.`), the empty-state body, and the textarea below. Composer height in this mode: 220px. Once any card exists, the composer reverts to the compact 56px form.

### `Overlay::Goal` (TUI)

- **Trigger keybinding:** **`G` (uppercase)** while focused on the Board view. **Not lowercase `g`** — lowercase `g` is reserved for "first row" vim semantics. Document `G` in the `Overlay::Help` panel under the Board section.
- **Lifecycle:** mirrors `Overlay::NewSession` exactly. Opens via `app.overlay = Overlay::Goal(GoalForm::default())`. Closes via `Esc` (cancel, no submit) or `Enter` (submit when textarea non-empty). `Enter` on an empty form is a no-op (no error, no close).
- **Layout:** centered modal block, ~60% width, ~40% height of the viewport (matches the `Overlay::NewSession` constants). Footer hint row: `Enter to plan · Esc to cancel`.
- **Visual:** outer block uses `palette.focus_border` for the border (electric blue equivalent), `palette.surface_bg` for the inner background, `palette.fg_strong` for the title bar text. Title: `GOAL`.
- **Multiline editing:** Enter inserts a newline; Cmd/Ctrl+Enter submits. (Note: TUI's existing newline conventions in `Overlay::NewSession` already differ from dashboard — keep TUI's behavior consistent with `NewSession`, not with the dashboard composer.) **Document the mismatch** in the overlay's footer hint: `Enter newline · Ctrl-Enter to plan · Esc cancel`.
- **Error surface (after failed submit):** error text replaces the footer hint, colored `palette.error`. Press any non-Esc key to dismiss.
- **Post-submit success:** overlay closes; the existing `/api/events` WS delivers the goal card; the board panel re-renders.
- **Status bar:** while overlay is open, the status bar shows `GOAL · planning…` (left-aligned, `palette.accent_alt`) until the submit returns; on success it returns to default.

### Parent-cue chip (both surfaces)

- **Dashboard:** rendered in the existing `.ticket .tk-foot` row, in the `.lbls` cluster on the **left** (before the lbl chips). One chip per child card. **Goal cards themselves do not render a parent-cue chip** (they have no parent in v1).
- **Click target (dashboard):** the chip is a `<button type="button">` with `aria-label="Open parent goal AG-{id}"`. Click opens the BoardItemDialog in edit mode for the parent goal id (`onclick={() => openCard(parentGoalId)}`). Keyboard: focusable via tab, activates via Enter or Space.
- **TUI:** rendered as a one-cell-tall row in the ticket card body, format `↳ AG-{id}` colored `palette.muted` (rendered before the card title). When the ticket is focused: the chip shifts to `palette.accent`. Pressing `o` on a focused child card with a parent jumps the board cursor to the parent card. (`o` for "open parent" — coexists with existing `o` semantics on sessions; in board context the binding is local.)
- **Optional grouping:** **NOT implemented in v1.** Cards stay flat in their column regardless of parent. Only the filter pill provides visual focus.

### Column filter pill

- **Activation:** clicking a parent-cue chip while no filter is active sets `boardFilter = { goalId: parentId }` in the local component state of `dashboard/src/routes/board/+page.svelte`. **Not persisted to URL in v1** — page reload clears the filter. (Deferred to a later phase if user demand surfaces.)
- **Scope:** the filter applies to the **column where the chip was clicked**, not the whole board. Cards in other columns render unchanged. The filtered column shows only: (a) the goal card itself if it's in this column, (b) any card with `parent_goal_id === goalId`. Other tickets are hidden.
- **Clear:** click the `×` on the pill, OR click any parent-cue chip again to toggle off, OR press `Esc` while the column is focused.

### `lbl="goal"` chip styling (extension of existing lbl variants)

- **New CSS rule** (alongside `.lbl.feat`, `.lbl.bug`, etc. in `_design.css`):
  ```css
  .ticket .tk-foot .lbl.goal {
    color: var(--cta);
    border-color: rgba(243, 100, 88, 0.4);
  }
  ```
- **Text inside the chip:** `GOAL` (uppercase, 9px mono — same as existing variants).
- **Goal card body:** unchanged from the default `.ticket` styling. The lbl chip carries the visual differentiator; no special border or background on the row itself. This is deliberate (CONTEXT D-02): "Distinguished visually by the `lbl="goal"` badge (existing lbl styling) and the new parent-cue UI".

## Mobile / PWA Behavior

PROJECT.md cites phone access as a core supported client. Composer must be thumb-friendly on viewports ≤720px:

- **Layout:** textarea above button, full width, 8px gap. Composer container padding stays 10px/16px.
- **Button:** min-height 38px (existing `.tb-btn.primary` mobile rule), full-width on the button row.
- **Textarea:** font-size auto-inflates to 16px (existing global rule in `app.css`).
- **No empty-state expanded mode on mobile** — the composer stays compact even when the board is empty. The board's existing `<EmptyState>` (already-shipped pattern) carries the "drop a goal in" framing instead. (Rationale: vertical real estate is precious on phones; the persistent bar must not eat the fold.)
- **Filter pill:** unchanged shape; tap target ≥36px tall on mobile (matches `.tb-btn` mobile rule).
- **Parent-cue chip on mobile:** tap target padded to ≥28px tall (current `.lbl` is ~12px tall — add a `@media (max-width: 720px)` rule bumping `.tk-foot .lbl` padding to 4px/8px).
