# Phase 2 — UI Design Contract

> Visual and interaction contract for the **Bound-session panel** in `BoardItemDialog.svelte`, the **back-link chip** on `/sessions/[id]/+page.svelte`, the **`[system]` comment row** treatment in the existing thread, the **crash visual state**, and the **TUI keybindings** that hop between cards and sessions. Generated by gsd-ui-researcher.

Phase 2 wires existing cards to existing sessions bidirectionally and routes watchdog events onto the card's comment thread. **No new global design tokens**, **no new components from scratch** — every surface specialises an existing primitive. `StatusPill.svelte` already exists at `dashboard/src/lib/components/StatusPill.svelte` (color-aware dot + uppercase mono label, idle / running / stopped / crashed) and is the canonical session-status visual; this spec reuses it verbatim.

**Audit findings (codebase scan 2026-05-21):**

- `dashboard/src/lib/components/StatusPill.svelte` already exists with the exact `Status = 'idle' \| 'running' \| 'stopped' \| 'crashed'` contract. Reuse verbatim — do NOT inline a duplicate `<span class="status-pill">`.
- **Gotcha:** CONTEXT D-13 references `GET /api/sessions/{id}/pane?lines=20` as if it exists. It does NOT. The session router at `crates/agentum-server/src/routes/sessions.rs:27-39` exposes only `/sessions`, `/sessions/{id}`, `.../start`, `.../stop`, `.../kill`, `.../send`, `.../stream` (WS). The planner MUST either (a) add a new `GET /api/sessions/{id}/pane?lines=N` route that wraps the existing `agentum_tmux::capture_pane_visible(target).await` helper, or (b) consume the existing `/stream` WS in a tail-only mode. **This spec assumes option (a)** — a small new route is simpler than threading a tail-only mode into the existing WS handler and matches CONTEXT D-13's polling cadence (2 s). The route surface is locked in §Component Inventory below.
- The TUI has **no Board panel / no card cursor / no `Focus::Board` variant**. The `Focus` enum in `crates/agentum/src/commands/terminal/app.rs:64` is `{ Tree, Term, TermRight, Lazygit }`. The Phase 1 Goal composer (`Overlay::Goal`) is the *only* board surface in the TUI; cards land in the dashboard. The orchestrator's brief assumed a TUI Board view that does not exist. Phase 2's TUI side ships **session-centric only**: `c` on a focused session that has a `card_id` reveals the card metadata in the status bar / a one-cell hint, and `s` is repurposed as a **board-side dashboard binding only** — see §Interaction Contract → TUI for the reconciliation. The full TUI Board view is deferred to Phase 3+ when the dependency-gate hits.
- `s` plain (no modifier) in TUI is **already bound** at `app.rs:4768` to "Stop the selected session" (`Overlay::Confirm(PendingAction::Stop { … })`). Phase 2 must NOT shadow it. See key-collision audit table in §Interaction Contract → TUI.
- `c` plain (no modifier) is **free** at the top-level handler (only `Ctrl-C` is used). Safe for "jump to bound card" semantics.

| Role | Value (token) | Usage in this phase |
|------|---------------|---------------------|
| Dominant (60%) | `var(--bg)` = `#0b0b0b` | Page canvas behind the dialog overlay backdrop; page canvas behind `/sessions/[id]` topbar. |
| Secondary (30%) | `var(--surface)` = `#212121` (panel surface, comment row surface) + `var(--bg-2)` = `#000000` (pane-tail inset, matches terminal black) | Bound-session panel container uses `--surface` to match `.claim-row`. | Accent (10%) | `var(--cta)` = `#f36458` (coral) | **Reserved for exactly these elements this phase:** (a) the "Open session →" link hover state (matches `a:hover { color: var(--accent) }` via legacy alias — note `--accent` resolves to `--link` in `_vars.css`; the actual coral usage is in the back-link chip when active, per (b)); (b) the back-link chip border + text turn `--cta` when the chip itself is focused/hovered. **Not used for the static state** — at rest the chip reads neutral. |
| Accent (interaction) | `var(--link)` = `#0052ef` (electric blue) | **Reserved for exactly these elements this phase:** (a) the `:focus-visible` outline on every focusable element (global rule); (b) hover state on the back-link chip text → `--link`; (c) hover on the "Open session →" button text → `--link`; (d) the `[system]` comment author's `[system]` prefix glyph (a 6px coral `●` dot inline OR — chosen variant — the literal `[system]` author rendered in `var(--fg-3)` muted gray to avoid stealing attention). **Resolved variant: muted (no extra accent).** Rationale below. |
| Destructive | `var(--crash)` = `#ff5555` | **Reserved for exactly these elements this phase:** (a) the status pill when `session.status === "crashed"` (inherited from `StatusPill.svelte` — it already paints `color: var(--danger)` with a 35% mix border on `[data-status="crashed"]`); (b) the body of any `[system] session crashed: …` comment row — a **2px left border** in `var(--crash)` and the body's `[system] session crashed: …` text rendered in `var(--fg-2)` (NOT in `--crash` — only the left border carries the signal). |

**Accent reserved for (exhaustive list):**

- Back-link chip hover/active states (`--cta` text + border on hover; `--link` on `:focus-visible`).
- "Open session →" link hover (text shifts to `--link`).
- The status pill's `running` state (`--green` via `--success` alias, inherited from `StatusPill.svelte`).
- The status pill's `crashed` state (`--crash` via `--danger` alias, inherited).
- The `[system] session crashed: …` comment's 2px left border (`--crash`).
- Global `:focus-visible` outline (`--link`).

**Explicitly NOT accent (anti-pattern guard):**

- `[system]` comment author label — **rendered in `var(--fg-3)`** (muted gray), NOT in `--cta`. Rationale: the existing `.cmt-author` rule paints non-system authors in `var(--cta)` to signal "human voice". System events are *background noise* relative to human comments — muting the author tag keeps them scannable but not noisy (CONTEXT D-06 verbatim: "visually distinguishable from human/agent comments but NOT noisy"). The `[system]` literal prefix in the body is the secondary signal.
- `[system] agent awaiting input` and `[system] agent finished` rows — **no left border**, no accent color anywhere in the row. They blend into the comment stream with only the muted author tag and the `[system] ` body prefix as cues. The crashed row is the **only** system row that gets a colored border (CONTEXT D-12: crashes are user-actionable; finishes and awaiting-input are status echoes).
- Pane-tail content — `var(--fg-2)` text on `var(--bg-2)` background. The pane's own ANSI escape codes are **stripped** before rendering (the existing `/stream` WS path keeps them; the new `/pane` snapshot path uses `capture_pane_visible` — no `-e` flag — so the snapshot is plain text). No syntax highlighting, no color.
- Bound-session panel container — neutral `--surface` like every other section row in the dialog. No special border. The eyebrow + status pill are the differentiators.

**Voice (locked):**

- All system-event copy is **observational and lowercase except the `[system]` literal**. No exclamations, no emojis. The user sees a stream of these and they must not feel chatty.
- Use the past-tense `agent finished` (not `agent done` or `agent completed`) and the present-progressive `agent awaiting input` (not `agent waiting for input`) — verbatim from CONTEXT D-06.
- The colon in `session crashed: <signature>` is **always present**, even when signature is `unknown`. This anchors the user's eye consistently and makes the signature substring parseable for support / grep.
- Back-link chip uses the Unicode `←` arrow (not `<-` or `&larr;`). The "Open session" button uses `→` (not `->`). These are explicit characters, not HTML entities.

## Interaction Contract

### Bound-session panel (`BoardItemDialog.svelte`)

- **Placement:** **above** the existing `.comments` section (`BoardItemDialog.svelte:892`). After the existing `Session` row in `.claim-row` (which already shows session id + Open/Start buttons), the new panel renders as a sibling block. Order from top of dialog: header → title → body → server → grid → agent → grid → claim row → **session row (existing)** → **bound-session panel (NEW)** → comments → footer.
- **Mount condition:** the panel renders **only when `card.session_id != null` AND the session GET resolves**. Fetch the session via `api.getSession(card.session_id)` on dialog open (cached for the dialog lifetime). On 404 (session was deleted) — replace the panel with a single muted line: `bound session no longer exists. unbind to clear the link.` and surface the existing Unbind button.
- **Three rows (vertical stack, gap: 8px):**
  1. Header row: `<span class="eyebrow">BOUND SESSION</span>` left, `<StatusPill status={session.status} />` right (existing component, no changes). Right-aligned via flex. The pill's color is automatically `green` on running, `muted` on idle/stopped, `red` on crashed.
  2. Pane-tail row: a `<pre class="pane-tail" aria-live="polite" aria-atomic="false">` block. 20 lines max. `max-height: calc(20 * 1.4em + 16px)` (line-height 1.4, padding 8px top/bottom). `overflow-y: auto`. The DOM updates on every successful poll — the `aria-live="polite"` polite-region announces only the **last appended line** to screen readers (browser default behavior — do NOT set `aria-atomic="true"` which would re-announce the whole 20-line buffer every 2 s). Polled via `setInterval(refreshPane, 2000)`; cancelled in the dialog's `$effect` teardown.
  3. Deep-link row: `<a class="open-session" href="/sessions/{session.id}">Open session →</a>`. Mono 11px, `var(--fg-2)` at rest, `var(--link)` on hover. Block-level so the whole row is clickable (the existing `Open session` button at `.claim-row:874` stays and is the canonical CTA — the deep link in the panel is a redundant convenience for users who skipped past the `.claim-row`).
- **Poll lifecycle:**
  - **Start:** when dialog opens AND `card.session_id != null` AND `session.status === "running"`. Skip for stopped/idle/crashed sessions (no pane output to fetch — show the "pane not active." empty state).
  - **Tick:** every **2000 ms** (CONTEXT D-13 verbatim).
  - **Stop:** on dialog close, on card.session_id becoming null (via re-render), on session.status changing to non-running, or on 3 consecutive errors (back off; show the polling-error empty state).
  - **Cancellation:** uses an `AbortController` per in-flight fetch so a slow request doesn't write into the panel after teardown.
  - **Visibility-pause:** when `document.visibilityState === "hidden"`, the interval is paused (matches the existing `events.ts` WS reconnect pattern). Resumed on visibilitychange.
- **Crash visual state (BIND-05, CONTEXT D-12):**
  - Card stays in `doing`. Card's column placement and dialog header unchanged.
  - `StatusPill` shows `crashed` (red).
  - Pane-tail block continues to render the last captured 20 lines (frozen — the watchdog has already marked the session crashed, so polling will return the stale snapshot). The pane-tail empty state copy switches to `pane not active.` after the next failed poll OR immediately when `session.status === "crashed"`.
  - A new `[system] session crashed: <signature>` row appears at the **bottom** of the comments thread (single comment per crash event, deduped by the watchdog bridge's `last_comment_kind: HashMap<Uuid, &'static str>` from CONTEXT D-07).
  - The Unbind button in `.claim-row` is rendered and ready — no auto-action.
- **Unbind action:**
  - Renders next to the existing Open-session button in `.claim-row` when `card.session_id != null`. Layout: `[Session: abc123… ]  [ Open session ↗ ]  [ Unbind ]` on one row. On `≤720px` it wraps.
  - Click flow: PATCH `/api/board/{card.id}` with body `{ "session_id": null }` (the new double-Option from CONTEXT D-10). Optimistic update: clears the panel immediately; rolls back on error. On success: the panel disappears, the `[system]` rows in the comment thread remain (history is preserved).
  - No confirmation modal. The action is reversible via the existing rebind flow (set `session_id` to a new uuid).
- **Rebind action (advanced):**
  - **Not exposed as a button in v1.** The user rebinds by typing or pasting a session UUID into the existing `session_id` editable field (if the dialog grows one) OR by using the dashboard's session picker. CONTEXT D-10 specifies PATCH-only; the dialog does not need a separate rebind UI in v1. **Deferred to a follow-up PR** if real usage shows demand.
- **Empty state (no `session_id` ever):** the existing `Session: none yet — Start session` row in `.claim-row` covers this case. The new Bound-session panel is simply not rendered.

### Back-link chip (`/sessions/[id]/+page.svelte`)

- **Placement:** in the existing `.toolbar` at the top of the page (`+page.svelte:162`). Inserts to the LEFT of the existing `.tabs` group, with an 8px right margin separating it from the Terminal tab.
- **Mount condition:** only when `session.card_id != null` AND the card GET resolves. Fetch via `api.getBoardItem(session.card_id)` on page mount + on every `reload()` tick (already polls every 5 s — piggyback). On 404 (card was deleted) — hide the chip and surface a small muted note in the topbar: `linked card was deleted.` (font matches the existing `.pill` text — mono 11.5px, `var(--fg-3)`).
- **Visual:** an `<a>` element styled as a `.pill`. Reuses the existing `.pill` rule in `+page.svelte` (lines around `:172` — already used for `pane: agentum-X`). New class additions: `.pill.back-link` for the hover treatment.
  - At rest: border `var(--border-2)`, text `var(--fg-2)`, background transparent.
  - Hover: border `var(--cta)`, text `var(--cta)`.
  - `:focus-visible`: 2px `var(--link)` outline + 2px offset (global rule from `app.css:92-96`).
  - Mono 11px (matches existing topbar pills).
- **Click behavior:** navigates to `/board?focus={card.id}`. Uses SvelteKit's `goto(...)` (same import the page already has at line 3) so the SPA transition is instant. The `?focus={card.id}` query param is consumed by `/board/+page.svelte` (existing or new behavior — Phase 1 reserved this query param for the "filter pill" pattern; see §Component Inventory below for the contract).
- **Truncation:**
  - Goal title `length <= 40`: render full title in quotes.
  - Goal title `length > 40`: render `goal_title.slice(0, 40)` + `…` (one Unicode ellipsis character, NOT three dots).
  - Card id, hash, and arrow are never truncated.
- **No parent goal case:** chip text is `← Card #{card.id}` (no parenthetical). Still rendered when `card_id` is set.
- **Mobile (`≤720px`):** chip is the FIRST element in the topbar (left edge); tabs collapse to a hamburger or scroll horizontally per the existing mobile rule. Tap target ≥36px (matches `.tb-btn` mobile rule). On viewports `≤540px`, the goal-title parenthetical is dropped entirely — chip degrades to `← Card #{N}` to save horizontal space.
- **Accessibility:** `<a>` element with `aria-label="Back to Card #{card.id} on the board"` (full label even when title is truncated). `:focus-visible` outline already covered by the global rule.

**Phase 2 TUI behavior locked:**

- Focus `Tree`, session has `card_id` selected:
  - Render ` c card #{id} ` chip on the right of the status bar (between the existing theme/status chips). `palette.muted` text on `palette.chrome_bg`.
  - Press `c`: toggle a one-cell-tall hint strip above the status bar showing `card #{id} — {title_truncated_to_72_chars}`. Background `palette.surface_bg`, text `palette.fg`. Pressing `c` again or `Esc` collapses it.
  - The hint does NOT take focus. The terminal continues to receive bytes.
- Focus `Tree`, session has no `card_id`:
  - No chip. `c` is a passthrough (no-op at the top-level handler — same as today).
- Focus `Term` / `TermRight` / `Lazygit`:
  - `c` is forwarded to the terminal PTY as it is today. No interception.
- The hint strip persists across session-switch within `Tree` focus (the user can `j` / `k` to walk sessions and watch the chip update). It auto-collapses when leaving `Tree` focus.

**Future-proofing note:** when a TUI Board view ships (Phase 3+ or v2), the mnemonic-symmetric pair becomes:
- Board view, card with `session_id`: `s` → jump to session pane (`Stop` will need a remap to e.g. `Shift-S` only — already the case in tree-focus bulk path).
- Session view, session with `card_id`: `c` → jump to card on board (today's "reveal hint" upgrades to "navigate to board view").

Phase 2 ships the session side of the pair; the board side is dashboard-only until then.

### `/board?focus={card.id}` query param contract

The back-link chip on `/sessions/[id]` navigates here. The `/board/+page.svelte` route is responsible for:

1. On mount, read `page.url.searchParams.get('focus')`. If present and parses to a positive integer, treat as a card id.
2. Scroll the matching ticket into view via the existing `scrollIntoView({ block: "center", behavior: "smooth" })` pattern. Highlight the row with a transient 2 s pulse: `box-shadow: 0 0 0 2px var(--link)` + `transform: translateY(-2px)` for 200 ms, then fade.
3. The focused state is **transient** — leaves the URL on next user interaction (drag, click, etc. — page must clear the param with `goto('/board', { replaceState: true })`).
4. If the card id doesn't match any ticket on the current board (e.g. card was deleted), show a toast: `Card #{id} not found on this board.` (existing toast pattern in `events.ts`).

This is **mostly an existing Phase 1 affordance**, called out here because the back-link chip is the canonical entry point and the spec must lock the contract.
