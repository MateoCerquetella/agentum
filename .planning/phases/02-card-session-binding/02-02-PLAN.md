       async fn pane(
           State(state): State<AppState>,
           Path(id): Path<Uuid>,
           Query(q): Query<PaneQuery>,
       ) -> Result<Json<PaneSnapshot>, ApiError> {
           let session = state.store.get_session(id).await?
               .ok_or_else(|| ApiError::NotFound(format!("session {id}")))?;
           let n = clamp_lines(q.lines);
           let captured_at = time::OffsetDateTime::now_utc()
               .format(&time::format_description::well_known::Rfc3339)
               .map_err(|e| ApiError::Internal(e.to_string()))?;
           let lines: Vec<String> = match session.tmux_target.as_deref() {
               Some(target) => {
                   let text = agentum_tmux::capture_pane_visible(target)
                       .await
                       .map_err(|e| ApiError::Internal(e.to_string()))?;
                   text.lines().rev().take(n).collect::<Vec<&str>>().into_iter().rev()
                       .map(|s| s.to_string()).collect()
               }
               None => Vec::new(),
           };
           Ok(Json(PaneSnapshot { lines, captured_at }))
       }

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→/api/sessions/{id}/pane | New GET endpoint accepting `{id}` (path Uuid) and `lines` (query u32). Bearer-auth required via inherited middleware. |
| server→tmux | Server shells out to `tmux capture-pane` via the existing `capture_pane_visible` helper. Target string is the session row's `tmux_target` column (server-controlled, never client-influenced). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Spoofing | Unauthenticated pane read | mitigate | Route lives under `/api/...` which the top-level `require_token` layer covers; `auth::is_public` is verified unchanged (acceptance criterion grep). |
| T-02-06 | Tampering | Client-controlled tmux target via path | mitigate | `Path<Uuid>` extractor parses the id; the server resolves `tmux_target` from `state.store.get_session(id)` — the client never names the tmux pane directly. |
| T-02-07 | Denial of service | Pane-capture amplification via large `lines=` | mitigate | `clamp_lines` server-side clamps to 1..=200. Test 2 + 3 prove the clamp. |
| T-02-08 | Information disclosure | Pane content leak to wrong user | mitigate | Pane content is what the user already sees in `/sessions/{id}` terminal panel and via `/stream`; same authz boundary, same data — no new leak surface. The user is authenticated; the session row is per-daemon, not per-user. |
| T-02-09 | DoS via 2 s polling × N tabs | rate-limit budget | accept | The dashboard polls 1 session at a time per open dialog; the daemon's existing access log compression handles burst absorption. If the polling cadence proves too aggressive in real usage, plan 05's lifecycle (visibility-pause + 3-error backoff) backs off automatically. |
| T-02-SC | Tampering | No new package installs in this plan | n/a | Code-only changes in one existing file; no `[dependencies]` additions; no slopcheck needed. |
</threat_model>
